# MapleStory CX26：B1 opt-in 安全首擊預熱 — 最小規格

> 狀態：**策略已用 V1／V2 驗證**；M0／M1 **實作仍待產品拍板**（本文件為規格，未實作注入碼）  
> 日期：2026-09-04（證據更新 2026-09-05）  
> 依據：[`maplestory-cx26-first-hit-prewarm-design.zh-TW.md`](maplestory-cx26-first-hit-prewarm-design.zh-TW.md)、[`maplestory-cx26-first-hit-materialize-findings.zh-TW.md`](maplestory-cx26-first-hit-materialize-findings.zh-TW.md)  
> 範圍：僅 **B1＝第一次「打到怪物」路徑的 materialize**；不含受擊／被動（B2）

## 1. 問題與目標

### 現象（已觀察）

- 對空氣普攻／攻擊技能：**順**
- **第一次打到怪物**：小卡～蠻卡（幅度不穩）
- 之後同 session 再打怪／換圖：多半順
- 被怪物打到、機率被動：另有 first-use（**B1 不承諾消除**）

### 目標（B1）

在使用者**明確 opt-in** 下，於進圖後、正式練功前，用一次（或極少次）**真實命中**，
把「命中特效／傷害字／怪物受擊」等路徑的 first-use 成本提前付掉，使後續第一次
「認真打怪」接近已預熱後的順暢。

### 非目標

- 不預設開啟；不承諾零卡頓
- 不自動觸發受擊／被動預熱（B2）
- 不依賴 `sample`／高干擾剖析當驗收
- 不加深 WZ `FAST_HIT`／不清／保 Metal disk cache 當本規格一部分
- 不修改 MapleStory.exe、不做封包級「假傷害」

## 2. 作法比較（實作落點）

| 作法 | 做法 | 優點 | 缺點 | 最小規格採納 |
|---|---|---|---|---|
| **M0 文件／提示** | Cyder 或 launcher 說明「進圖後先打一下怪」 | 零注入、零防作弊面 | 非自動化 | **必做**（任何自動化之前） |
| **M1 單次鍵注入** | 地圖就緒後，短窗內注入 1 次普攻鍵（僅當判定可打時） | 對齊已證實「真命中才暖到」 | 防作弊／誤傷／鍵位 | **實驗 flag 候選** |
| **M2 完整戰鬥預熱** | 多技能、多段、強制找怪 | 覆蓋廣 | 超出最小；風險高 | **不做** |

**建議：** 先核准 **M0 + M1 實驗旗標規格**；產品預設只上 M0，M1 預設關、僅進階／開發。

## 3. 行為規格（M1）

### 3.1 開關

| 項目 | 值 |
|---|---|
| Env／進階選項名（暫定） | `CYDER_MAPLESTORY_HIT_PREWARM=1` |
| 預設 | **0／關** |
| UI | 若進 Cyder：進階選項，文案須含「會自動攻擊附近怪物一次」風險說明 |
| Engine | 不讀到 flag 則完全無行為 |

### 3.2 觸發條件（全部滿足才動作）

1. Flag 開啟  
2. 偵測到「可操作 ingame」（沿用既有 present／視窗／loading 結束訊號；**不**在登入／選角／黑屏）  
3. 自就緒起進入 **預熱窗**（建議預設 **5s**，可調 `…_HIT_PREWARM_WINDOW_MS`）  
4. 預熱尚未成功／尚未放棄  
5. **安全門檻**（見 §3.4）通過  

### 3.3 動作

1. 在預熱窗內，最多嘗試 **1 次** 普攻鍵注入（鍵碼：該角色預設普攻；**不做**技能輪詢）。  
2. 成功條件（擇一即可，實作時用可觀察代理）：  
   - 注入後短時間內出現命中相關呈現（若無可觀測 API，則以「已注入且窗內未取消」為弱成功，體感驗收為準）；或  
   - 開發 log：`CYDER_HIT_PREWARM fired=1`  
3. 無論成敗，**每個 Wine 遊戲行程最多觸發一輪**（不換圖重做；換角／重開遊戲才重置）。  
4. 逾時或安全門檻失敗 → 安靜放棄，不重試洗版。

### 3.4 安全門檻（「安全首擊」）

最小版採 **保守啟發式**（寧可不動，勿亂打）：

| 規則 | 最小版 |
|---|---|
| 僅普攻 | 是 |
| 次數 | ≤1 |
| 時間窗 | 短（預設 5s） |
| 偵測「面前有怪」 | **若無法可靠偵測 → 不注入**（退回 M0 提示） |
| 城鎮／無怪圖 | 不注入 |
| 使用者輸入 | 窗內若偵測到鍵盤／滑鼠戰鬥輸入 → **取消**預熱 |
| 預設關閉 | 是 |

> 若第一版做不到可靠「有怪」偵測，**M1 不得上產品**；只保留 M0，M1 留在設計待感測就緒。

### 3.5 明確不做

- 不注入技能鍵、不連打、不鎖定血量％  
- 不模擬受擊、不點觸發被動  
- 不在 loading 或非前台時注入  
- 不把失敗打成錯誤彈窗干擾（最多一次低調提示，可關）

## 4. 驗收（體感，不開 `sample`）

固定：同角色、同安全練功圖、GPTK／D3DMetal、`FILE_CACHE=1`、`FAST_HIT=0`。

| 輪 | 條件 | 期望 |
|---|---|---|
| T0 | flag 關，不揮空首打 | 基線：小卡～蠻卡（已知波動） |
| T1 | flag 開，允許一次安全首擊完成後，再「認真打」 | 第二次起打怪 **明顯優於 T0 首打**（多為順或近順） |
| T2 | flag 開但無怪／門檻失敗 | 行為＝不注入；首打仍可能卡（可接受） |
| T3 | 硬失敗 | 防作弊異常、誤傷任務 NPC、進圖明顯變慢 → **立即關 flag、不合併** |

每組 ≥2 次體感；不開 macOS `sample`。

### 4.1 手動驗證「首擊預熱是否有用」（B1.1，無注入碼）

在實作 M1 前，用手動扮演「預熱首擊」：

| 步驟 | 動作 | 記錄 |
|---|---|---|
| P0 | 冷啟動進圖；**不要**對空氣 | — |
| P1 | **故意打到一隻怪一次**（付預熱成本） | 這一擊：蠻卡／小卡／無感 |
| P2 | 接著連續打怪／放技能 10～20 秒 | 是否「都很順」、有無第二下又卡 |
| P3（對照，可另開一局） | 冷啟動；只對空氣；再打第一下怪 | 第一下打到怪是否仍卡 |

**判定：**

- 若 P1 有卡、P2 明顯順 → **B1 預熱有用**（把成本提前到 P1）
- 若 P2 仍反覆卡 → B1 不夠，需再查（被動／受擊／其他）
- 若 P3 第一下仍卡、且不優於「沒揮空的首打」→ 揮空不能替代 B1（已有證據）

結果記入玩測表與 `/private/tmp/cyder-cx26-fasthit-play-logs/e2-result-and-e3-prepare.txt`。

### 4.2 B1.1 手動結果（2026-09-04 ~21:01）

| 步驟 | 結果 |
|---|---|
| P1 故意首擊打到怪 | **小卡** |
| P2 後續 10～20 秒 | **都很順** |

使用者後續澄清（~21:06）：這與「第一下本來就會卡、之後不會」是**同一現象**；「預熱後更順」可能只是體感誤差。  
**最重要的痛點仍是第一下命中卡頓本身**，不是後續是否順。

**對 B1／M0 的正確解讀：**

| | 能否改善「第一下打到怪的卡」 | 實際差異 |
|---|---|---|
| **什麼都不做** | 否；卡在使用者開始認真練的那一下 | 痛點落在「正要開打」的心理時刻 |
| **M0（提示先打一下）** | **否**；第一下照樣付費 | 只把同一下卡頓**提前**到進圖後自願試刀，並降低「怎麼突然卡」的意外感；**不減少**卡頓幅度 |
| **M1（自動首擊）** | **否**；自動打出的那一下仍會卡 | 與 M0 相同，只是代打「付費那一下」；後面變順是本來就會發生的事 |
| **真要優化第一下** | 需降低命中路徑 first-use 絕對成本（資源／PSO／轉譯等），或接受 known issue | 超出 M0／M1 最小規格 |

因此：B1.1 **不能**當成「證明預熱讓第一下變順」；只證明 session 內付過一次命中成本後不再卡（已知）。  
M0 的產品價值若存在，是 **預期管理＋時機轉移**，不是消卡。

### 4.3 證據強化：V1／V2（2026-09-05）

完整數據與 Instruments 細節：  
[`maplestory-cx26-first-hit-materialize-findings.zh-TW.md`](maplestory-cx26-first-hit-materialize-findings.zh-TW.md)

| 實驗 | 結果 | 對 B1／M0／M1 |
|---|---|---|
| **V1** Hit1 vs Hit2 + Metal System Trace | Hit1 小卡＋Present／Frame **~749 ms** 空窗；Hit2 不卡、無第二段大空窗 | 卡頓＝**首次命中 materialize**（量化） |
| **V2** HitA 故意首打 → HitB 正式第一下 | HitA 小卡；**HitB 不卡** | **預付策略有效**（與本規格目標一致） |
| Instruments A | hitch 內 encoder 停、CPU 偏 `AGXBuffer init` | 命中首用建 Metal buffer 堵出幀；**不是**揮空／WZ 預熱能解 |
| H1／H2／DXMT／H3-B | 皆未消掉「付費那一下」幅度 | 強化「M0／M1 只改時機」；隱形假暖不可行 |

**產品表述（核准實作時必須沿用）：**

- 不承諾「第一下不卡」  
- 承諾「進圖先打一下後，認真練時較不易突然卡」  
- 付費那一下仍可能小卡／HUD 整片停約 0.5–0.8 s 量級（本機實測）

壓低 **付費那一下本身** 的絕對成本：見 findings §6；目前引擎範圍內無已驗證辦法。

## 6. 風險與文案要點

必須讓使用者知道：

- 會在進圖後短暫自動攻擊附近怪物一次  
- 可能造成誤傷、吸怪、任務干擾  
- 與遊戲 ToS／防作弊相關風險由 opt-in 自負  
- 關閉選項後行為與現況相同  

Engine／Cyder **預設關閉**；文件與 UI 不得寫成「保證不卡」。
